**Major S1 — missing or malformed XML-stage execution can be counted as a successful rejection.**

Locations: `family-run/summarize.py:30–35,50–64`; underlying unchanged bridge policy at `family-run/snapshots/Oracle.java:89–103`. Related reporting weakness: `discriminant/run_v2.py:80–91` marks a returned, bound JSON record `observed` without checking its processing/stage state; `discriminant/report_results.py:15–25,38–54` then emits unconditional successful-processing prose.

For `rejected`, a record with `processing == completed`, an empty stage map, schema/business `not_evaluated`, and even an undefined reference recommendation satisfies the checked consistency relations. Its batch completeness predicate checks the processing string, not whether the required evaluation actually happened. The bridge's fallback also maps a processing-successful but incomplete evaluation to `rejected`.

Executed reproduction: the synthetic `missing_all_stages` fixture changes only the baseline record to that shape and updates the corresponding synthetic stream/receipt hashes. The summarizer returns `complete`, zero contract errors, and 33 rejected/27 accepted. The `malformed_xml_completed` fixture supplies only `val-xml: invalid`; it receives the same successful batch classification. These are contract probes, not claims that the pinned KoSIT run produced those states.

For the publication verifier, distinguish a completed invalid XSD check from absent execution. Require evidence of XML-stage execution and the applicable stage progression. A completed invalid XSD result can remain a schema rejection with later stages explicitly not evaluated; missing stages without a supported earlier terminal validation result, malformed/failed execution, undefined recommendation, exceptions, and timeouts must not be manufactured into accepted/rejected evidence. Preserve the raw bridge value and attach a separate verification/classification error rather than rewriting historic labels. Derive discriminant prose from verified records and process outcomes too.
