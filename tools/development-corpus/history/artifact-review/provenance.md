## Findings

1. **Minor — `complete` does not independently verify several provenance bindings.** In `.scratch/bsc10/expansion/family-run/summarize.py:23–28`, the checker validates only part of the input/output receipts. It omits the output receipt's request ID, ordinal and `evaluate_returned`, and the input receipt's closure/driver/freeze/ledger hashes. At lines 50–59 it trusts the evaluation process metadata without checking its command or stdout/stderr hashes against the retained command and streams. Disposable copies with (a) an impossible evaluation command and false stream digests, (b) output ID `a-different-request`, ordinal `999`, and `evaluate_returned=false`, or (c) false input provenance hashes each still returned `True`, `status=complete`, and zero contract errors. The untouched control returned complete; nonzero evaluation exit and altered bridge output were detected. Reproduction: `provenance/audit.py`, function `synthetic`; exact commands, altered copies and generated reports are in `provenance/audit-attempt-04/`, with the compact result in `synthetic-results.json`. A future reporting revision should cross-check these fields and process command/stream bindings before claiming complete provenance. The immutable outer manifest plus this review's independent checks catch these contradictions in the present evidence; all actual originals passed those stronger checks.

2. **Minor — the corrected discriminant helper omits launch-error outcome records.** `.scratch/bsc10/expansion/discriminant/run_v2.py:22–35` catches `TimeoutExpired`, but an `OSError` while starting a process escapes before stream files, metadata, or an `outcomes` entry are written. The outer `finally` at lines 92–94 consequently cannot include that attempted process in its outcome list. `provenance/launch_error_probe.py` extracts the exact verified helper AST and actually attempts to execute a nonexistent binary in the disposable subtree: `FileNotFoundError` propagates, the command is retained, and the metadata/stdout/stderr files and outcome entry are absent. See `provenance/launch-error-probe-01/probe-result.json` and its declaration for source hash, original line span and exact argv. A future runner revision should record launch errors explicitly, as the family runner already does at `family-run/run.py:45–60`. No actual retained discriminant launch suffered this failure; all four first-attempt nonzero exits and all four second-attempt outcomes are present. This finding concerns complete retention on reproduction failures, not invoice verdicts.
